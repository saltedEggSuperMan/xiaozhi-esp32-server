# 小智硬件接线、本地部署与调试总结

记录日期：2026-10-20。覆盖本会话从开发板接入、音频调试、PC 外放、网易云音乐，到 ST7789 屏幕和 Otto 动态表情的实施过程。

项目目录：`D:\xiaozhi-esp32\xiaozhi-esp32-server`。

本文根据会话中的用户反馈、设备串口日志、实际烧录记录及项目文档整理。标注为历史记录或待处理的事项，不代表已经完成修复；服务地址、串口和 Windows 默认音频设备在换网络或重新插拔后需要重新核对。本文不包含密码、API Key、登录 Cookie、管理令牌或可重复使用的激活码。

## 1. 最终可用状态

目前采用以下组合：

```text
INMP441 麦克风 → ESP32-S3 → Wi-Fi → 本机小智服务
                                      ├─ 语音回答 → 笔记本扬声器
                                      ├─ 网易云音乐 → 本机 mpv → 笔记本扬声器
                                      └─ 状态、文字及表情 → ESP32-S3 → ST7789
```

| 项目 | 最终方案与验证结果 |
| --- | --- |
| 收音 | 开发板连接 INMP441，继续使用开发板麦克风 |
| 回答外放 | `server_pc`，由运行 Python 语音服务的笔记本播放 |
| 原功放 | MAX98357A 已拔除；当前 PC 模式不需要接回 |
| 唤醒 | “你好小智”；短按 BOOT 可用于固件支持的开始对话/打断操作 |
| 显示 | ST7789 1.54 寸 IPS、240×240、8 针带 CS |
| 固件 | 自编译 `v2.2.4`，板型目标为 `bread-compact-wifi-lcd` |
| 表情 | Otto 21 种动态 GIF，适配为 128×128，黑底白字，保留状态和对话文字 |
| TTS | 本会话最终选择 Edge；保留本地 TTS 为可选项 |
| 音乐 | 网易云账号资源与本地文件两种来源可切换 |
| 恢复音乐 | 说“继续播放”直接恢复，不再先播报确认语音 |
| 配网及设备标识 | 本次分段烧录、资源更新均保留，重启自动联网 |
| 最终实测 | 用户确认“显示正常，动画流畅”“回应和表情都正常” |

PC 外放只改变播放出口，USB 串口仍用于开发板供电和调试；设备与服务端之间的语音、控制和显示数据通过 Wi-Fi 传输。PC 模式也不会把收音设备自动换成笔记本麦克风。

## 3. 最终接线

所有 GPIO 编号均指开发板丝印的 GPIO 编号，不是排针从上往下的序号。改线前先断开 USB 等电源，各模块与开发板共地。

### 3.1 INMP441 麦克风：当前保留

| INMP441 引脚 | ESP32-S3 连接 |
| --- | --- |
| VDD / VCC | 3V3 |
| GND | GND |
| L/R | GND，选择左声道 |
| WS | GPIO4 |
| SCK | GPIO5 |
| SD | GPIO6 |

拔除功放不应同时拔掉麦克风的 3V3、GND 或 L/R 接地。PC 模式仍依赖这只麦克风唤醒和收音。

### 3.2 ST7789 屏幕：当前保留

| ST7789 引脚 | ESP32-S3 连接 | 功能 |
| --- | --- | --- |
| GND | GND | 地 |
| VCC | 3V3 | 屏幕供电 |
| SCL | GPIO21 | SPI 时钟 CLK |
| SDA | GPIO47 | SPI 数据 MOSI |
| RES | GPIO45 | 屏幕复位 |
| DC | GPIO40 | 数据/命令选择 |
| CS | GPIO41 | SPI 片选 |
| BLK | GPIO42 | 背光控制 |

这块屏幕虽然将数据和时钟标作 SDA/SCL，本次使用的是 **SPI** 接法。不能按 OLED 的 I2C 接线或固件配置使用。

用户有两个 3V3 针脚。当前功放已移除，可将两个 3V3 分别用于 INMP441 和屏幕，当前组合不再需要为功放额外分出 3V3。

### 3.3 MAX98357A：历史接法，当前不接

以下信号 GPIO 与本次 LCD 固件的 I2S 单工配置一致，用于以后恢复原音频模块时核对。

| MAX98357A 引脚 | 历史连接/说明 |
| --- | --- |
| VIN | 开发板 5V 供电端 |
| GND | GND |
| DIN | GPIO7 |
| BCLK | GPIO15 |
| LRC / LRCLK | GPIO16 |
| SD | 早期接法使用 3V3 使能；恢复时核对所持模块定义 |
| GAIN | 用户后期明确描述为悬空；没有确定一套已消除失真的增益接法 |
| 喇叭 | 接模块扬声器输出 `+`、`-`，不将其中一端当作普通 GND |

当前无需连接这一模块。以后恢复它，需要同时将回答音频模式切回 `device`，并重新验证供电、音量和播放效果。不要把 VIN 悬空当作增益调整方式。

## 4. 本地部署与日常操作

### 4.1 地址和服务约定

以下是本会话使用的局域网地址及本项目启动约定，不是保证永远不变的固定地址。

| 服务/用途 | 地址或端口 |
| --- | --- |
| PC 局域网地址 | `192.168.0.102` |
| 开发板最近启动获得的地址 | `192.168.0.100`；早期也曾获得 `.104`，以 DHCP 当前结果为准 |
| 开发板 OTA 地址 | `http://192.168.0.102:8002/xiaozhi/ota/` |
| 开发板 WebSocket | `ws://192.168.0.102:8000/xiaozhi/v1/`，由本地 OTA 配置下发 |
| 本机智控台 | `http://127.0.0.1:8001` |
| 本机 Java 管理后端 | `http://127.0.0.1:8002/xiaozhi` |
| Python 语音服务 | 8000；视觉接口为 8003 |
| 浏览器测试页 | `http://127.0.0.1:8006/index.html` |
| 音乐管理服务 | `127.0.0.1:8007`，通过 `music.cmd --open` 打开 |
| 项目数据库 | MySQL 8，使用 3307；不混用其他项目的 3306 实例 |
| 缓存 | Redis 6379，项目专用逻辑库 15 |

开发板访问 PC 时使用 PC 的局域网地址，不使用 `127.0.0.1`。换路由器、改变 PC 地址后，需要重新核对 OTA 和下发的 WebSocket 地址。

### 4.2 配网及绑定顺序

1. 启动本地服务，检查 OTA 接口可用。
2. 在开发板配网页的高级选项中先填写本地 OTA 地址，再填写 Wi-Fi 名称和密码并退出配网。
3. 查看日志中是否获得 IP、访问本地 OTA、进入激活或待命状态。
4. 未绑定时，从屏幕或串口读取**当次**激活码，在本地智控台将硬件绑定到智能体。
5. 绑定成功后测试“你好小智”和普通问答。

早期没有屏幕、喇叭时，使用 COM3 串口查看激活码。删除绑定后需要重新完成绑定，不应沿用历史日志中的旧激活码。早期直接向串口发送 `ws_url ...` 后仍访问官方激活服务，不能以“发送过字符串”作为设置生效的证据；最终通过配网页保存 OTA 地址并查看新日志确认生效。

### 4.3 启动、重启与关闭

在项目根目录执行：

```powershell
Set-Location 'D:\xiaozhi-esp32\xiaozhi-esp32-server'

# 交互选择回答外放方式和音乐来源
.\start-all.cmd
.\restart-all.cmd

# 明确选择当前方案，跳过交互
.\start-all.cmd -AudioOutput server_pc -MusicSource netease
.\restart-all.cmd -AudioOutput server_pc -MusicSource netease

# 仅检查，不重启
.\start-all.cmd -Check

# 关闭项目服务
.\stop-all.cmd
```

- 回答出口支持 `server_pc` 与 `device`；音乐来源支持 `netease` 与 `local`。
- 交互时回车沿用上次选择；启动器复用健康服务，音频配置改变时会按需要重启语音服务。
- 关闭脚本核对进程归属，保留 MySQL/Redis、配置和数据库数据；完整脚本也管理已安装的音乐服务及播放器。
- 电脑必须开机且语音服务正常运行，PC 外放才能工作。

### 4.4 实际本机音频覆盖配置

本次整理时已读取 `main/xiaozhi-server/data/.config.yaml` 的以下非敏感字段：

```yaml
audio_output:
  mode: server_pc
  pc:
    device: null
    volume: 0.6

speech_response:
  tts_mode: configured
  vad_silence_ms: 400
```

`device: null` 表示跟随 Windows 默认输出，插上耳机可能转到耳机。`configured` 表示沿用原业务配置的 TTS；本会话最终切回 Edge。本地完整部署中的模型、音色等业务配置由智控台管理，不应仅凭仓库默认 `config.yaml` 推断实际生效配置。

语音外放软件音量 0.6、Windows 系统音量、网易云音乐音量是不同的控制项。整理时音乐设置为 `source: netease`、音量 49，约 50%。

常用诊断与切换：

```powershell
.\audio-output.cmd
.\audio-output.cmd --list-devices
.\audio-output.cmd --mode server_pc --device default --volume 0.6 --test
.\audio-output.cmd --mode device
```

手动改变回答音频配置后需重启 Python 语音服务，或使用启动/重启脚本应用选择。测试音只用于确认声卡出口，不代表完整对话链路已经正常。

## 5. 音频和语音调试过程

### 5.1 无反应、无声音与绑定问题

早期出现过说话无反应、短按 BOOT 后仍没有反馈、后台已合成回复但喇叭完全没声音等现象。中途用户曾删除设备绑定，需要重新获取激活码绑定。

排查中逐步将问题拆分为：设备是否启动并联网、是否绑定智能体、是否检测到唤醒/收到音频、是否生成回答，以及回答是否实际播放。用户重新接线后，原喇叭开始有声音，说明早期硬件音频链路确实需要处理；本会话未留下一项可证明所有早期“无反应”都由同一个原因造成的证据。

最终麦克风接线固定为第 3.1 节，当前已通过 PC 回答和屏幕表情的实测验收。

### 5.2 4 Ω、3 W 喇叭沙哑、沙沙声

使用 MAX98357A 与 3525 腔体喇叭时，用户反馈音质较差，降低音量后稍有改善，但升到约 60% 时失真明显。期间尝试过重新接线、讨论 GAIN 和供电，并试过充电宝供电。

这些现象提示功放增益、供电、接触、喇叭及失真都值得检查，但没有完成电压/波形测量或逐项替换，因此不能认定已证明是某一个模块损坏或功率不足。充电宝测试时出现过无反应、进入配网模式及重复“嘟嘟”声，也缺少足够日志确定原因。

**最终处置：改为 PC 外放，MAX98357A 拔除。原喇叭的大音量音质问题暂缓处理，不作为已经修好的项目记录。**

### 5.3 小爱音箱 LX05 作为外放的尝试

用户希望用现有小爱音箱提升外放音质。实际操作时，音箱提示需要先在 App 关闭蓝牙网关才能使用相应蓝牙播放功能，而用户必须保留网关控制家电。

本会话因此未将 LX05 接入播放链路，转用笔记本自带扬声器。这里记录的是用户当时设备提示及选择，没有完成该音箱不同固件下并发功能的全面验证。

### 5.4 PC 外放开发与声卡问题

新增可配置回答出口，开发板继续收音，Python 服务通过 sounddevice 在 PC 播放；设备继续收到文字和播放状态。

曾出现提示音未听到、插拔耳机后输出位置变化。低音量短提示不容易判断，后续较清楚的两秒变调提示音及更大音量测试由用户确认听到。排查时不能只根据后台“已生成音频”判断物理扬声器一定发声。

后续修复了旧连接长期持有 PC 播放锁的问题：输出流可以缓存复用，但全局播放锁只在实际播放一轮回答时占用，避免空闲旧连接阻塞新连接。用户随后确认唤醒回应恢复。

主要实现：`main/xiaozhi-server/core/utils/pcAudioOutput.py`。详细使用见 [PC 外放配置](pc-audio-output.md)。

### 5.5 说完话到听到回答的延迟

历史排查发现等待由多段叠加：VAD 静音判定、ASR、LLM、Edge 合成、音频转换以及声卡打开/缓冲。其中观察到 Edge 限流重试也会拉长个别回答。

已完成并保留：

- 将本机有效静音等待从 700 ms 调到 400 ms。
- 同一连接复用 PC 声卡，减少每轮重新打开设备的成本。
- 增加不带对话原文的部分毫秒级计时。
- 修复播放锁释放，保持重连后可正常外放。

试用 Windows SAPI 的 Microsoft Huihui Desktop 本地 TTS 后，用户反馈“明显更快”，但认为声音像机器人、质量不如 Edge。最终恢复 Edge，同时保留上述延迟优化和可选本地引擎。

历史小样本中 Edge 收齐一段约 1.1～1.3 秒，Huihui 首次约 255 ms、预热后约 8～63 ms；这些是合成阶段测试，不能直接当作完整问答耗时。**Edge 收到网络 MP3 块后立即增量解码播放尚未实现。**

```powershell
# 可选本地引擎，不是当前默认
.\audio-output.cmd --tts-mode windows_local --vad-silence-ms 400

# 回到配置的 TTS，本会话选择为 Edge
.\audio-output.cmd --tts-mode configured
```

## 6. 网易云音乐功能与问题处理

### 6.1 最终实现

在保留原本地音乐播放能力的基础上，增加网易云账号 API 模式。采用本机桥接服务和 mpv 播放，不是遥控桌面网易云客户端，也不读取桌面客户端登录文件。

| 组件 | 作用 |
| --- | --- |
| Node 音乐桥接服务 | 管理页、来源切换、账号资源及播放控制 |
| 网易云 API 依赖 | 本机安装使用 `@neteasecloudmusicapienhanced/api` 4.41.1 |
| mpv | 在服务端 PC 播放音乐，使用系统音频输出 |
| Sherpa ONNX KWS | 音乐播放期间在本机检测“你好小智” |

已实测：扫码登录、读取喜欢列表/歌单、播放账号有权限的歌曲、暂停、继续、停止，以及本地与网易云来源切换。一次约 12 秒、50% 音量的真实歌曲试播，用户确认听到音乐。

```powershell
.\music.cmd --source netease --open
.\music.cmd --status
.\music.cmd --source local
.\music.cmd --source netease
.\music.cmd --action pause
.\music.cmd --action resume
.\music.cmd --volume 49
```

音乐设置保存在 `.runtime/music/settings.json`。账号由本项目独立扫码授权，Cookie 使用当前 Windows 用户的 DPAPI 加密保存在 `.runtime/music/account.dpapi`；不要分享该文件或管理令牌。

### 6.2 卡在“读取状态”，误以为账号隔天失效

原因是直接访问 `http://127.0.0.1:8007/` 的新页面没有本机管理凭据，不等于网易云账号已过期。

解决：使用 `music.cmd --open` 打开带本机授权的管理页，并改进前端的未授权、超时及错误提示，避免一直停在“读取”。用户随后确认页面显示已登录。只有账号检查确实判定网易云授权失效时才重新扫码。

### 6.3 音乐播放时，唤醒词无法暂停

初版在音乐期间丢弃普通麦克风音频以避免歌词进入 ASR，但开发板已处于自动拾音时，不会总是重新发送独立的唤醒事件，导致无法靠唤醒词打断音乐。

解决：音乐期间收到的 PCM 只进入本机 Sherpa ONNX 中文关键词检测；检测到“你好小智”后先暂停音乐，再恢复普通语音对话。未命中的音乐音频不送入普通 ASR/LLM，也不增加该路径的录音保存。

用户确认音乐能够暂停、小智能回复，并可继续播放。

### 6.4 重启后“继续播放”无反应

已确认并修复两个软件问题：

1. 快速意图词表没有覆盖“继续播放”等短说法。
2. 缓存唤醒回复结束后的拾音保护与队列积压，会吞掉紧接着说的短指令。

处理：补齐“继续播放”“恢复播放”“暂停播放”；唤醒回复结束后清理回复期间积压音频并立即恢复正常拾音。用户实测确认恢复正常。

### 6.5 恢复音乐前先语音确认，听起来“卡一下”

用户确认只有声音停顿，鼠标和画面没有一起卡顿，因此不能据此认定整台 PC 性能卡死。

按用户要求修改：成功执行“继续播放/恢复播放”时直接恢复歌曲，不调用确认 TTS，也不播放结束提示音；失败仍提示原因。用户确认“直接播放，符合预期”。

### 6.6 音乐较响或离麦克风较远时唤醒变慢

用户靠近麦克风后恢复。音乐声会遮盖唤醒词；PC 扬声器的声音没有作为开发板的声学回声参考输入，本次关键词检测不等于完成了 PC 外放的声学回声消除。

目前采用适当降低音乐音量、调整扬声器与麦克风位置、靠近麦克风等方式改善。没有宣称已实现远场、强音乐背景下可靠的全双工打断。

“直接说停”能否打断还取决于当前拾音状态与固件支持；已验证的可靠交互是先说“你好小智”或使用 BOOT，再发控制指令。

网易云仅播放账号接口返回且具备完整播放权限的资源，不绕过会员、单独购买、地区或试听限制。第三方 API 不是网易云官方稳定性承诺；后续接口变化可能需要维护。完整说明见 [网易云音乐](netease-music.md)。

## 7. ST7789 屏幕固件编译与烧录

### 7.1 为什么原固件不能直接接屏使用

早期使用 `v2.2.4_bread-compact-wifi.zip`，该板型按 OLED 配置，不是本次 ST7789 SPI LCD 配置。

| GPIO | 原 `bread-compact-wifi` 用途 | 新 LCD 接线用途 |
| --- | --- | --- |
| GPIO47 | 触摸按键 | 屏幕 SDA/MOSI |
| GPIO40 | 音量增加按键 | 屏幕 DC |
| GPIO41 | OLED SDA | 屏幕 CS |
| GPIO42 | OLED SCL | 屏幕 BLK |

用户接上屏幕、拔除功放后无法唤醒。COM3 复位日志确认仍运行旧固件，日志停在 `CompactWifiBoard: SSD1306 driver installed` 附近，未进入联网阶段。

根据引脚用途冲突更换 LCD 固件后，屏幕、联网与语音均恢复。没有进一步证明旧固件内部究竟卡在哪一个底层等待函数，因此本文不将某个未经验证的底层异常写成已确认根因。

### 7.2 编译目标和环境

| 项目 | 本次采用 |
| --- | --- |
| 用户下载源码 | `D:\devEnvironment\xiaozhi-esp32-2.2.4`，保留原始目录 |
| 工作副本 | `.runtime/fw244/src` |
| ESP-IDF | 5.5.2，位于 `.runtime/fw244/esp-idf-v5.5.2` |
| 独立 Python/工具链 | `.runtime/fw244/tools/`；不复用服务端虚拟环境安装 IDF 工具 |
| 芯片目标 | `esp32s3` |
| 板型 | `CONFIG_BOARD_TYPE_BREAD_COMPACT_WIFI_LCD=y` |
| 屏幕 | `CONFIG_LCD_ST7789_240X240=y`，带 CS 的 8 针型号 |
| Flash / PSRAM | 16 MB Flash；8 MB 八线 PSRAM，80 MHz |
| 语言/唤醒 | 中文；AFE + `wn9_nihaoxiaozhi_tts` |
| 编译默认 OTA | `http://192.168.0.102:8002/xiaozhi/ota/` |

官方该版本没有适用于本板的 `bread-compact-wifi-lcd` 预编译包，因此自行编译。名称相似的 `bread-compact-esp32-lcd` 属于经典 ESP32 目标，不能替代本次 ESP32-S3 镜像。

构建完成后检查了芯片镜像头、分区边界、分段与合并镜像内容以及校验值。首次运行构建器时出现 Ninja 无法定位，改为解析完整 `ninja.exe` 路径后完成构建。

SDK 配置包含 QIO 选项，但本次 IDF 生成的实际烧录参数为 **DIO / 80 MHz / 16 MB**；烧录脚本按照 `flasher_args.json` 和包内清单执行，不只凭配置名称推断模式。

### 7.3 分区和烧录文件

| 内容 | 地址 | 说明 |
| --- | --- | --- |
| bootloader | `0x0` | 启动程序 |
| partition table | `0x8000` | 分区表 |
| NVS | `0x9000`，长度 `0x4000` | 配网、设备标识等；本次保留 |
| OTA data | `0xD000` | OTA 启动选择数据 |
| PHY init | `0xF000` | PHY 初始化分区 |
| ota_0 应用 | `0x20000` | 本次 LCD 主程序 |
| ota_1 | `0x410000` | 另一个 OTA 应用槽 |
| assets | `0x800000`，长度 `0x800000` | 8 MB 字体、唤醒模型及表情资源 |

先通过 COM3 备份分区表/NVS，并确认新旧分区布局一致，再执行分段烧录；未全片擦除。写入后校验通过，设备标识保持一致，自动连接 Wi-Fi，进入 `activating -> idle`，唤醒模型和麦克风启动。

2026-10-19 用户确认屏幕显示正常、PC 能听到唤醒回应。

## 10. 后续出现问题时的排查顺序

1. **先看启动和联网**：COM3 是否仍对应开发板，复位日志是否识别正确板型、获得 IP、进入待命。
2. **再看服务和绑定**：运行 `start-all.cmd -Check`；核对 PC 局域网地址、OTA 与智能体绑定。
3. **区分没唤醒与没播声**：是否出现唤醒/状态切换；若服务已回复但没声音，检查 Windows 默认输出、耳机和 PC 音量。
4. **麦克风不收音**：核对 INMP441 的 3V3、共地、L/R 接地及 GPIO4/5/6，避免拔功放时带走麦克风接线。
5. **屏幕异常**：核对 SPI 引脚、8 针带 CS 的屏幕选择和 LCD 固件目标，不能套用旧 OLED 固件。
6. **音乐页未授权或一直读取**：先用 `music.cmd --open` 重新打开，不要直接认定网易云登录已失效。
7. **音乐中唤醒较差**：先降低音乐音量并靠近麦克风，检查本地音乐 KWS；当前没有完整 PC 外放回声消除。
8. **资源更新后异常**：保留串口日志；必要时用 `-Restore` 恢复默认资源，区分资源问题与固件/硬件问题。

串口监视器和烧录工具不能同时占用 COM3。接线与参数已经在当前板上验证通过时，应优先读取新日志定位变化，不要反复全片擦除、恢复出厂或无依据地重新绑定。
