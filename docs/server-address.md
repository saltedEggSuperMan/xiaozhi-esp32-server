# 电脑 IP 改变后，通过 USB 同步地址

适用本项目已经编译并验证的 ESP32-S3 N16R8、v2.2.4 LCD 固件及其 16 MB 分区布局。
使用项目内 ESP-IDF 工具，服务端凭据从本机配置读取，不需要重新输入 Wi-Fi 密码或绑定设备。

1. 用之前的 USB 调试口将开发板接回电脑，关闭占用 COM3 的串口工具。
2. 双击 `start-all.cmd` / `restart-all.cmd`，在可选改址提示中填写 IP、WS 端口、OTA 端口和 COM 口。任一步直接回车则不处理改址，继续启动；填完整后服务就绪才执行同步。

也可先启动本地项目服务，再从项目根目录执行，新 IP 替换为实际地址：

```powershell
.\server-address.cmd --host 192.168.0.100 --port COM3 --apply

# 同时明确指定设备访问的端口
.\server-address.cmd --host 192.168.0.100 --ws-port 8000 --ota-port 8002 --port COM3 --apply
```

脚本会备份分区表/NVS，核对分区布局与 CRC，然后更新：

- 智控台的 `server.websocket` 和 `server.ota` 主机地址。
- Redis 中这两个参数的缓存字段；不清空其他缓存或逻辑库。
- 设备 NVS 中 `wifi.ota_url` 和 `websocket.url` 的主机地址。

设备端只写 NVS 的 `0x9000` 分区。Wi-Fi 名称/密码、设备标识、认证字段等其他字节保持原样；不刷应用、分区表和 Otto 资源。结束后自动复位设备。

不加 `--apply` 只备份、预览并复位，不写入地址。由于需要读取 Flash，预览也会暂时中断设备当前会话。

限制：支持已有私网 IPv4 地址，保留原 URL 的协议及路径；端口可单独指定，不指定时保留原端口。它不改变服务监听配置，写入前会验证新 WS/OTA 地址可用。不会自动覆盖域名、远端公网地址、含额外认证参数的 URL。新 URL 必须放得下原 NVS 分配的空间，否则拒绝更新，不清除配网。操作失败时查看提示的私有备份目录，必要时短按 RST 恢复运行，不要自行全片擦除。

备份位于 `.runtime/server-address-<时间>/`。其中 NVS 含 Wi-Fi 和设备凭据，不要上传或分享。

## 避免反复改址

在路由器 DHCP 设置中，为笔记本的 Wi-Fi 网卡保留一个地址，可减少 IP 改变带来的重新配置。改用其他网络或网段时仍需要核对地址；Windows 使用随机硬件地址时，也要注意 DHCP 保留是否匹配实际网卡标识。

本工具由用户填写地址后执行，不会在跳过输入时自动修改设备，也未声称已配置路由器或实现 mDNS 自动发现。

原 LCD 固件包编译时的默认 OTA 仍为 `192.168.0.102`。设备正常运行时优先使用本工具更新的 NVS 地址；以后全片擦除、清空 NVS 或刷入完整镜像后，要重新设置地址。分段保留 NVS 的升级不会因此自动退回旧地址。

## 本次实测（2026-10-22）

- 笔记本 Wi-Fi IP 从 `192.168.0.102` 变为 `192.168.0.100`；开发板本次获得 `.102`，不要把它与服务端混淆。
- 服务端下发的 WS、OTA 下载地址及设备已保存的 OTA/WS 地址均同步到 `.100`。
- 新局域网 OTA 地址测试通过；设备日志确认访问 `.100:8002`、进入待命并加载唤醒模型。
- 用户唤醒并提问后确认“已恢复正常”。本次无需重新配网、绑定或更新表情。
